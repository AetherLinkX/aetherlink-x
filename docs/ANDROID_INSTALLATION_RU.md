# AetherLink X Client для Android

## Что входит в сборку

Android-клиент использует `VpnService`, HEV SOCKS5 TUN и собственный
`libv2ray.aar`, собранный из Xray-core `v26.7.28` с патчем AetherLink X. Это
важно: стандартное ядро Xray не знает протокол `aetherlinkx` и не сможет
подключиться к такому inbound.

Поддерживаются AetherLink X, VLESS, VMess, Trojan, Shadowsocks, Hysteria2,
TUIC, AnyTLS, WireGuard/WARP, SOCKS5 и HTTP. Для потоковых протоколов доступны
RAW TCP, WebSocket, gRPC, XHTTP, HTTPUpgrade, mKCP и Hysteria transport.
Ссылки старого формата `type=h2` и `type=quic` автоматически преобразуются в
XHTTP `stream-one` поверх HTTP/2 и HTTP/3, потому что отдельные legacy H2/QUIC
транспорты удалены из актуального Xray.

Версия 0.5 сохраняет из share-ссылок XHTTP-поля `mode` и `extra`, а также
связанные с TLS/REALITY значения `alpn`, `flow` и `spx`. Параметры padding,
xmux и upload/download из `extra` передаются ядру без самовольной замены.
Повреждённый необязательный `extra` сбрасывается к значениям Xray по умолчанию,
не делая весь профиль непригодным.

TCP и UDP устройства перехватываются одним TUN-интерфейсом. DNS идёт через
тот же туннель и правило `dns-out`; прямого системного fallback нет.

## Установка готового APK

1. Откройте GitHub Releases репозитория AetherLink X.
2. В prerelease `client-dev` скачайте
   `aetherlink-x-client-android-universal-debug.apk` и файл SHA-256.
3. Сверьте контрольную сумму файла.
4. Разрешите Android установить APK из выбранного браузера или файлового
   менеджера и установите приложение.
5. При первом подключении подтвердите стандартный системный запрос VPN.

Debug-APK подписан отладочным ключом. При переходе на будущую release-подпись
Android может потребовать удалить alpha-версию перед установкой.

## Импорт подписки Remnawave

1. Скопируйте персональную ссылку вида `https://.../sub/...`.
2. На экране «Серверы» нажмите «Вставить» либо откройте ссылку прямо в Android.
3. Клиент скачает подписку, распознает Base64, список share-ссылок или полный
   Xray JSON, создаст профили и активирует первый корректный профиль.
4. Нажмите центральную кнопку подключения.

При обновлении Remnawave-подписки клиент также сохраняет название сервиса,
сайт, ссылку поддержки, объявление и данные расхода/лимита. Главная страница
показывает их над полным списком локаций именно выбранной подписки.

### Если Remnawave не выдал локации

Remnawave может вернуть служебные VLESS-записи `0.0.0.0:1` с текстом вроде
«Приложение не поддерживается», когда пользователь не входит в нужный Internal
Squad или для него не найден подходящий хост. Это не сервер и подключение к нему
невозможно. Начиная с клиента 0.6 такие записи отбрасываются, подписка остаётся
в приложении с нулём локаций и понятным сообщением, а клиент дополнительно
проверяет совместимый JSON-вариант ответа. После добавления пользователя в
нужный squad достаточно нажать «Обновить».

Сам клиент не может обойти серверную выдачу доступа: для реального подключения
пользователь должен состоять в Internal Squad, связанном с нужным inbound/хостом.
Кнопка «Полностью удалить профиль» удаляет саму подписку и все её локальные
локации; обычное обновление ничего лишнего не удаляет.

Также поддерживаются QR-коды и прямые ссылки `aetherlinkx://`, `vless://`,
`vmess://`, `trojan://`, `ss://`, `hysteria2://`, `tuic://`, `anytls://`,
`wireguard://`, `socks5://`, `xhttp://` и `alxclient://`.

Никому не передавайте URL подписки, UUID, ALX account secret, закрытый ключ
REALITY или закрытый X-Wing ключ.

## Переключение сервера во время работы

Список профилей находится прямо на главной странице. Нажатие другого сервера
при включённом VPN выполняет управляемую замену: клиент останавливает HEV и
старый Xray loop, освобождает локальный SOCKS-порт, создаёт новый конфиг и
поднимает туннель снова внутри того же `VpnService`. Новый запрос разрешения
Android не нужен. Короткий разрыв соединений во время смены сервера ожидаем.

Android разрешает только один системный VPN. Приложение не завершает чужие
процессы (это невозможно без root), но после подтверждения системного диалога
Android отзывает VPN у ранее активного приложения.

## Проверка пинга

В «Настройки → Подключение» доступны:

- AetherLink Ping — три HTTPS GET через активный туннель, показывается медиана;
- TCP Connect — три прямых TCP-подключения к адресу и порту сервера;
- HTTP GET и HTTP HEAD — end-to-end проверка через активный туннель;
- ICMP — системный Android `ping` без подстановки shell-команд.

Там же задаются тестовый HTTPS URL и вид индикатора: цифры, шкала, шкала с
цифрами или точки. Для сравнения всех серверов используется TCP Connect,
поскольку один активный SOCKS-туннель не может одновременно измерять разные
outbound-профили.

## Локальная сборка

Требуются JDK 21, Android SDK/NDK, Go и Gradle 9.4.1. Рекомендуемый способ —
запустить workflow `Build AetherLink X Client (Android)` в GitHub Actions: он
сам применяет `patches/aetherlinkx-xray-core-v26.7.28.patch`, собирает AAR,
HEV-библиотеки, скачивает geodata, запускает тесты и создаёт APK.

Для ручной сборки повторите команды из
`.github/workflows/build-aetherlinkx-client-android.yml`. Не подменяйте AAR
обычным Xray: APK соберётся, но inbound/outbound AetherLink X будет неизвестен.

## Настройка сервера

1. Соберите Xray-core с тем же ALX-патчем или используйте опубликованный
   AetherLink X Remnawave Node image.
2. Создайте уникальные UUID и 32-байтовый Base64URL account secret.
3. Добавьте пользователя в ALX inbound и используйте тот же secret на клиенте.
4. Для публичного сервера включите TLS либо REALITY. Небезопасный транспорт
   разрешайте только в изолированной тестовой сети.
5. Значения Turbo, inner AEAD, Stealth и PQ/X-Wing на клиенте и сервере должны
   быть совместимы; расхождение политики приводит к отказу handshake.

Подробности Remnawave находятся в `remnawave/README.md` и
`docs/AETHERLINK_X_CLIENT_REMNAWAVE.md`.

## Диагностика

- «Не удалось распознать ссылку»: вставляйте весь URL без пробелов; HTTP(S)
  обрабатывается как подписка, а не как одиночный прокси-профиль.
- gRPC не подключается: проверьте `serviceName`, SNI и HTTP/2 на reverse proxy.
  Ведущий `/` допустим только для расширенного custom-path синтаксиса Xray.
- WS/HTTPUpgrade: путь и Host должны совпадать с inbound/reverse proxy; ALPN —
  `http/1.1`.
- H2/QUIC: обе стороны должны использовать современный XHTTP-вариант. Старый
  сервер с удалённым legacy transport несовместим с Xray v26.7.28.
- REALITY: поддерживается только с RAW, XHTTP и gRPC.
- UDP не работает: проверьте, что серверный outbound разрешает UDP, а firewall
  и облачная security group не блокируют нужные порты.
- DNS: включите диагностический журнал и проверьте правило `dns-out`, FakeDNS и
  доступность настроенного DoH.
- Полный kill switch включается в Android через «Постоянный VPN» и
  «Блокировать подключения без VPN».

## Ограничения безопасности

AetherLink X остаётся экспериментальным и не проходил независимый
криптографический аудит. Не считайте динамические отпечатки или padding
гарантией невидимости для DPI. Перед production нужны внешний review,
межоперационные тесты, длительные soak/race тесты и испытания с loss/jitter.
