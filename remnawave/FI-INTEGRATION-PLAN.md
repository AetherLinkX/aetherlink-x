# Безопасное подключение AetherLink X к профилю FI

## Проверенное исходное состояние

- Панель: Remnawave Backend `2.7.4` с ALX static patch.
- Профиль `FI`: восемь валидных VLESS + REALITY inbound.
- Занятые профилем порты: `3945`, `9613`, `4673`, `7851`, `2083`,
  `3081`, `4081`, `2096`.
- Назначенная нода работает на Remnawave Node `3.2.2` и Xray `26.7.28`.

Существующие inbound нельзя переименовывать, удалять или заменять. ALX
добавляется девятым inbound с новым уникальным tag и только на свободном TCP
порту, подтверждённом командой `ss -lntup` непосредственно на ноде.

## Обязательный порядок

1. Сохранить копию текущего JSON профиля FI и compose-файла ноды.
2. Проверить свободный порт на ноде. Для REALITY предпочтителен `443`, но он
   используется только если действительно свободен; запасной вариант — `8443`.
3. Переключить ноду на ALX-образ с той же базовой версией Node `3.2.2`.
4. Проверить healthcheck, версию Xray и старые восемь inbound.
5. Добавить ALX как девятый inbound, не меняя остальные секции FI.
6. Создать отдельный Internal Squad `AetherLink X FI`, не меняя существующие
   squads, и привязать к нему только `AETHERLINK_X_MANAGED_FI`.
7. Добавить в новый squad одного тестового пользователя, проверить выдачу
   Xray JSON/URI, handshake, трафик и немедленный revoke.
8. Только после успешного revoke-теста добавлять нужные подписки.

## Почему static inbound нельзя просто добавить в squad

Текущая интеграция хранит ALX `id` и `secret` непосредственно в JSON профиля.
Remnawave `2.7.4` не создаёт, не удаляет и не публикует такие credentials для
обычных пользователей. Поэтому добавление static inbound в squad создаёт
ложное ощущение разграничения доступа: членство в squad не отзывает уже
выданный static secret.

Static-режим остаётся только для ручного доступа и не смешивается с FI.

## Реализованный managed-режим

Согласованный адаптер Panel 2.7.4 + Node 3.2.2 реализует:

- инъекцию только пользователей выбранного Internal Squad;
- динамические add/remove операции через HandlerService;
- уникальный secret из `ssPassword` с фиксированным KDF context;
- raw `aetherlinkx://` и Xray JSON subscription output;
- безопасный пустой squad: Xray запускается с нулём ALX users и отклоняет все
  handshakes;
- изоляцию от static inbound через обязательный tag-префикс
  `AETHERLINK_X_MANAGED_`.

Patch, Backend build и Node typecheck прошли локально. До завершения
multi-arch container CI и end-to-end revoke-теста production squads не
изменяются.

## Откат

Если новая нода не проходит healthcheck или отклоняет профиль:

1. вернуть исходный image в compose;
2. поднять только сервис ноды;
3. вернуть сохранённый JSON FI;
4. подтвердить доступность всех восьми исходных inbound.

Изменения базы данных не требуются ни для static-, ни для managed-режима.
